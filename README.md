# מוקד אחזקה — "ליוסי פנית, לא טעית" 🔧

מערכת מלאה (שרת + מסד נתונים + התחברות אמיתית) לדיווח ותיעדוף תקלות אחזקה במפעל.
כל המחלקות מדווחות דרך אותו אתר, וצוות האחזקה (יוסי והצוות) מתעדף, משייך ועוקב — הכול משותף בזמן אמת.

## מה יש כאן

- **שרת Node.js (Express)** עם API אמיתי, ומסד נתונים **SQLite** (קובץ יחיד, לא דורש התקנת שרת מסד נתונים נפרד).
- **התחברות אמיתית** לצוות האחזקה (שם משתמש + סיסמה מוצפנת), מבוססת עוגיית session.
- דיווח מהמחלקות **פתוח לכולם ללא התחברות** (כדי לשמור על מהירות הדיווח) — כפי שהיה בגרסת ההדגמה.
- העלאת תמונות/סרטונים אמיתית לשרת (לא רק בזיכרון הדפדפן).
- כל מי שנכנס לאתר (מכל מכשיר) רואה את אותם הנתונים, ומתעדכן אוטומטית כל כמה שניות.
- **תמיכה בשלוש שפות ממשק: עברית, ערבית ותאילנדית** — ראו "שפות הממשק" למטה.
- קובץ `render.yaml` מוכן מראש — מאפשר פריסה כמעט-אוטומטית לשירות Render (ראו "פריסה לאוויר" למטה).

## שפות הממשק (עברית / ערבית / תאילנדית)

בפינה השמאלית העליונה (ליד "צוות אחזקה") יש כפתורי שפה: **עברית / العربية / ไทย**. לחיצה על אחד מהם מתרגמת מיידית את כל הממשק — כותרות, תוויות, כפתורים, הודעות מערכת וכו' — כולל כיוון תצוגה נכון (עברית וערבית מוצגות מימין לשמאל; תאילנדית מוצגת משמאל לימין). כל דפדפן/מכשיר זוכר את בחירת השפה שלו באופן עצמאי (נשמר מקומית בדפדפן), כך שכל עובד יכול לבחור את השפה הנוחה לו בלי להשפיע על מה שרואים אחרים.

**חשוב לדעת:**
- תוכן שמוזן על ידי המשתמשים עצמם — שמות תקלות, תיאורים, שמות מחלקות/ציוד/עובדים/ספקים שהוגדרו על ידכם — **נשאר תמיד בשפה שבה הוזן** (בדרך כלל עברית) ואינו מתורגם אוטומטית. מתורגם רק הטקסט הקבוע של הממשק עצמו (תוויות, כפתורים, הודעות).
- הסטטוס והדחיפות של תקלה (למשל "חדש"/"בטיפול"/"הושלם") **נשמרים במסד הנתונים תמיד בעברית**, ללא קשר לשפת התצוגה שנבחרה — כך שכל המשתמשים, בכל שפה, תמיד מסתכלים על אותו מידע עקבי; רק האופן שבו הם *מוצגים על המסך* מתורגם.
- התרגום לערבית ולתאילנדית הוכן בעזרת בינה מלאכותית ונבדק שהוא תקין ומובן, אך **מומלץ מאוד לבקש מדובר שפת אם לעבור על הממשק לפני הטמעה רחבה בקרב העובדים**, כדי לוודא שהניסוח טבעי ומדויק מבחינה מקצועית/תעשייתית.

## הרצה מקומית (על המחשב שלכם)

דרישה: [Node.js](https://nodejs.org) גרסה 18 ומעלה מותקן על המחשב.

```bash
cd moked-achzaka-app
npm install
npm start
```

השרת יעלה בכתובת: **http://localhost:3000**

בהרצה הראשונה נוצר אוטומטית קובץ מסד נתונים (`data/app.db`) עם נתוני דוגמה — מחלקות, ציוד, אנשי צוות ומשימות לדוגמה — בדיוק כמו בגרסת ההדגמה שראיתם.

> **אם `npm install` נכשל עם שגיאה שמזכירה `node-gyp` או `better-sqlite3`** (קורה לפעמים ברשתות ארגוניות עם חסימות פיירוול): נסו `npm install --ignore-scripts` במקום זאת. הספרייה `better-sqlite3` מגיעה עם קבצים מהודרים מראש לרוב מערכות ההפעלה הנפוצות, כך שהאפליקציה עדיין תעבוד תקין גם בלי שלב ההידור המקומי.

### כניסה כצוות אחזקה

לחיצה על הכפתור "🛠️ צוות אחזקה" תבקש שם משתמש וסיסמה. משתמשי ברירת המחדל שנוצרים אוטומטית:

| שם | תפקיד | שם משתמש | סיסמה |
|---|---|---|---|
| יוסי | מנהל אחזקה | `yossi` | `yossi123` |
| מוחמד | עוזר אחזקה | `mohamed` | `mohamed123` |
| עובד אחזקה 3 | עוזר אחזקה | `worker3` | `worker3123` |
| עובד אחזקה 4 | עוזר אחזקה | `worker4` | `worker4123` |

⚠️ **חשוב מאוד:** אלה סיסמאות ברירת מחדל גנריות המיועדות רק להרצה ראשונה/בדיקה. לפני שנותנים למישהו אמיתי להשתמש במערכת — כל אחד מהצוות צריך להתחבר ולהחליף סיסמה דרך הקישור **"שינוי סיסמה"** שמופיע לצד השם המחובר בפינה השמאלית העליונה. (ל"— תקן פנוי —" ולספקים חיצוניים אין התחברות בכלל — הם רק שם לשיוך משימות.)

## איפה שומר הנתונים

- מסד הנתונים: `data/app.db` (קובץ SQLite יחיד).
- קבצים שהועלו (תמונות/סרטונים): בתיקיית `uploads/`.

**גיבוי:** מספיק להעתיק את התיקייה `data/` ואת התיקייה `uploads/` כדי לגבות את כל המידע.

## הגדרות סביבה (מומלץ לפני עלייה לאוויר)

העתיקו את `.env.example` לקובץ בשם `.env` ומלאו:

```bash
cp .env.example .env
```

- `SESSION_SECRET` — מחרוזת סודית וקבועה. בלעדיה, כל הפעלה מחדש של השרת מנתקת את כולם. ליצירת ערך אקראי:
  ```bash
  node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
  ```
- `PORT` — הפורט להרצה (ברוב שירותי האחסון בענן זה מוגדר אוטומטית ואין צורך לגעת בו).

## פריסה לאוויר — מדריך מלא מאפס (Render), בלי צורך בניסיון קודם

כרגע המערכת רצה רק על המחשב שהפעיל אותה. כדי שכל המפעל יוכל להיכנס מהטלפון/מהמחשב שלהם, צריך להעלות אותה לשירות אחסון בענן. המדריך הזה מניח שאין לכם עדיין שום חשבון (לא GitHub, לא Render) — הולכים צעד-צעד.

**שלב 1 — פתיחת חשבון GitHub (חינמי, כמה דקות)**

GitHub הוא המקום שבו "שמים" את קוד האפליקציה כדי ששירותי אחסון כמו Render יוכלו למשוך אותו ולהריץ אותו.

1. גשו ל-[github.com](https://github.com) ולחצו על **Sign up**.
2. מלאו אימייל, סיסמה ושם משתמש, ואשרו את החשבון (יישלח מייל אימות).

**שלב 2 — יצירת "מאגר" (Repository) חדש והעלאת הקבצים**

1. אחרי ההתחברות, לחצו על הכפתור הירוק **New** (או על ה-**+** למעלה מימין ואז **New repository**).
2. תנו שם, למשל `moked-achzaka` (אין חשיבות לשם באנגלית/עברית, רק בלי רווחים). השאירו את הגדרת ה-**Private/Public** כמו שהיא (מומלץ Private אם יש אפשרות, כדי שאף אחד זר לא יראה את הקוד).
3. **חשוב:** אל תסמנו "Add a README file" — משאירים את המאגר ריק לגמרי. לחצו **Create repository**.
4. תגיעו לדף עם הוראות — תחפשו קישור/כפתור בשם **"uploading an existing file"**.
5. חלצו (unzip) את הקובץ `moked-achzaka-app.zip` שקיבלתם ממני במחשב שלכם, ואז **גררו את כל תוכן התיקייה** (כל הקבצים והתיקיות שבפנים — לא את התיקייה עצמה עם השם שלה, אלא מה שבתוכה) לתוך אזור ההעלאה בדפדפן. גיטהאב שומר את מבנה התיקיות הפנימי (`public/`, `data/`, `uploads/` וכו') אוטומטית.
6. גללו למטה, כתבו הודעה קצרה כמו "העלאה ראשונה" בתיבת ה-commit, ולחצו **Commit changes**.

**שלב 3 — פתיחת חשבון Render וחיבור אותו ל-GitHub**

1. גשו ל-[render.com](https://render.com) ולחצו **Get Started**. הכי נוח להירשם עם **"Sign up with GitHub"** — זה גם פותח חשבון וגם מחבר אותו לגיטהאב בבת אחת, בלי כרטיס אשראי.
2. אשרו לרנדר גישת קריאה למאגרים שלכם ב-GitHub כשתתבקשו (אפשר להגביל את הגישה רק למאגר `moked-achzaka` הספציפי).

**שלב 4 — פריסת האפליקציה עם קובץ ה-Blueprint המוכן**

בתוך התיקייה שקיבלתם יש קובץ בשם `render.yaml` — הוא כבר מכיל את כל ההגדרות (פקודת התקנה, פקודת הרצה, ואפילו יצירה אוטומטית של מפתח האבטחה `SESSION_SECRET`), כך שלא צריך למלא כלום ידנית:

1. בדשבורד של Render, לחצו **New** ← **Blueprint**.
2. בחרו את המאגר `moked-achzaka` שיצרתם.
3. Render יזהה את `render.yaml` אוטומטית ויציג את השירות שמוגדר בו (`moked-achzaka`, תוכנית Free). לחצו **Apply** / **Create**.
4. חכו כ-2-3 דקות שהבנייה (Build) תסתיים. כשהסטטוס יהפוך ל-**Live**, תראו למעלה כתובת כמו `https://moked-achzaka.onrender.com` — זו הכתובת הקבועה שכל המפעל ייכנס אליה מכל מכשיר.

**שלב 5 — בדיקה ראשונה**

1. פתחו את הכתובת שקיבלתם מ-Render.
2. נסו להתחבר כ"צוות אחזקה" עם `yossi` / `yossi123` (ראו טבלת המשתמשים למעלה), ומיד אחר כך **תחליפו סיסמה** דרך "שינוי סיסמה".
3. שלחו את הכתובת לצוות ולמחלקות — זהו, המערכת חיה.

⚠️ **מגבלה חשובה בשכבה החינמית של Render:** שירות חינמי "נרדם" אחרי 15 דקות בלי תנועה (הכניסה הראשונה אחרי שינה כזו לוקחת כדקה), וחשוב מזה — **הדיסק החינמי אינו קבוע (ephemeral)**. זה אומר שקובץ מסד הנתונים (`data/app.db`) והתמונות שהועלו (`uploads/`) **עלולים להימחק** בכל פריסה מחדש (למשל אם תעדכנו קוד ותעלו שוב) או הפעלה מחדש של השירות. זה בסדר לגמרי כדי להתחיל ולבדוק עם הצוות, אבל **לא מתאים כפתרון קבוע לנתונים אמיתיים לאורך זמן**.

כדי לפתור את זה כשתרצו לעבור לשימוש רציני: בדשבורד של השירות ב-Render, בלשונית **Disks**, מוסיפים דיסק קבוע (Persistent Disk) בתוספת תשלום קטנה (כ-0.25$ לחודש לכל GB) ומצמידים אותו לנתיב `/opt/render/project/src/data` (ואם רוצים גם את התמונות — דיסק נוסף על `/opt/render/project/src/uploads`). זה דורש שדרוג מהתוכנית Free לתוכנית בתשלום (Starter ומעלה).

### אלטרנטיבה — Railway

Railway כן כולל דיסק קבוע (volume) גם בתוכנית הבסיסית, אבל נכון להיום **נדרש כרטיס אשראי** גם לתוכנית החינמית/ניסיון (מקבלים קרדיט חודשי קטן בחינם, ומעבר לו מחויבים). התהליך דומה: להעלות ל-GitHub, ואז ב-Railway לבחור "Deploy from GitHub repo".

### חשוב לדעת

- לא הרשמתי/יצרתי בשבילכם חשבון באף שירות (לא GitHub ולא Render), ולא הזנתי פרטי תשלום — זה שלב שאתם צריכים לעשות בעצמכם. אני יכול להמשיך להדריך שלב-שלב אם משהו לא ברור בדרך.
- לאחר שהמערכת עולה לאוויר, היא מקבלת **HTTPS** אוטומטית וללא עלות נוספת (גם ב-Render וגם ב-Railway) — אין צורך להגדיר שום דבר בנושא הזה.
- כל עדכון עתידי לקוד: מעלים את הקבצים המעודכנים לאותו מאגר ב-GitHub (באותו אופן, דרך "Add file" → "Upload files"), ו-Render יפרוס אותם מחדש אוטומטית תוך דקות.

## מה השתנה לעומת גרסת ההדגמה המקורית

- הנתונים נשמרים בשרת אמיתי ולא בזיכרון הדפדפן — הם לא נעלמים ברענון ומשותפים לכולם.
- הכניסה כ"צוות אחזקה" דורשת שם משתמש וסיסמה אמיתיים (מוצפנים) במקום בחירת שם מרשימה.
- העלאת תמונות/סרטונים נשמרת בפועל בשרת.
- מסך המחלקה מתעדכן אוטומטית כל כמה שניות כדי להראות עדכונים חדשים ממי שעובד עליהם.

כל שאר הפיצ'רים (יומן טיפול, תאריכי יעד, שיוך לצוות/ספקים, מעקב עלות וחשבוניות, חיפוש וסינון, ייצוא ל-CSV/הדפסה וכו') זהים לגרסת ההדגמה שאושרה.
